# Stage 2 brief: Bus parcel desk

**Track:** Go · **Mode:** 1, you type everything · **Time:** 2–3 months (estimate) · Read `house-rules.md` first.

## The problem
Parcels travel between towns on upcountry buses. At the counter a clerk writes a reference by hand on the parcel and in a book. The receiver is told by phone call, if at all, and at the far end anyone who knows the name can walk off with the parcel. Parcels get lost, and nobody can say where one was last seen or who handed it over.

## Goal
A parcel desk for one bus company with several stations: a JSON API and a small server-rendered counter screen, on PostgreSQL, written with **the Go standard library for everything except the database driver, the query generator and the migration tool**. No web framework and no router package. It is deployed as one binary on a Linux server.

## Build
**The service:**
1. **Structure.** A small `main` that calls a testable `run` function; a function that builds the whole `http.Handler` from its dependencies; one file that lists every route; code under `cmd/` and `internal/`; dependencies passed to constructors, no globals. Config comes from environment variables.
2. **Routing and middleware.** `net/http` with the built-in router's method and wildcard patterns. Middleware you write yourself for request logging, panic recovery, "must be logged in", role checks and CSRF on the counter forms. Server timeouts are set, not left at zero.
3. **Logging and context.** `log/slog` with a request id on every line. `context` is the first parameter of every function that touches the database, and a cancelled request stops its query.
4. **Database, in two steps.** First write the parcel intake and lookup with `database/sql` by hand, with placeholders and a transaction. Then move the data layer to pgx with code generated by sqlc. Keep one hand-written query in the README with the generated version beside it and say what changed. Migrations run with goose from the command line.
5. **Login.** Clerks and station managers log in with a password stored with a slow hash. The counter screen uses a session cookie; the API uses a token. Pick sessions or JWT for each and write down why.

**The parcel desk:**
1. **Stations and staff.** A clerk belongs to one station. A manager sees their station's reports.
2. **Intake.** The clerk records sender name and phone, receiver name and phone, destination station, a short description, and the carriage fee paid (recorded only, in whole shillings). The system issues a tracking reference that is short, hard to guess the next one from, and safe to read aloud over a bad phone line.
3. **Hand-overs.** Every change of hands is a new record, never an edit: received at counter, loaded on a bus (with the bus registration), unloaded at destination, held for collection, collected, returned. Each record has who, where and when.
4. **Arrival notice.** When a parcel is unloaded at its destination, a notice for the receiver is written to an outbox table in the same transaction, in the receiver's language, with a collection code. A separate command of the same binary (`parcel send-notices`, run on a timer) sends pending notices through a `Sender` interface. The first sender writes to the log; a sender for an SMS simulator is optional.
5. **Collection.** The parcel is released only when the collection code is entered at the destination counter. The code is stored hashed, and wrong attempts are counted and limited.
6. **Tracking.** A public page and API endpoint that show a parcel's current status and station from its reference, and nothing about the people.
7. **Screens.** A counter screen with `html/template`: intake, today's parcels, hand-over, collection. Kiswahili and English, switchable, Kiswahili by default. Pages are light and work on a phone. Lists are paginated.
8. **Tests.** Table-driven handler tests with `httptest`, and tests for the hand-over rules.
9. **Deployed.** Cross-compile one static binary, copy it to a Linux server you set up, run it under systemd behind HTTPS, with the timer for notices and a database backup.

## Edge cases you must handle
- The same intake form is submitted twice (double click, or the network dropped and the clerk tried again): one parcel.
- A parcel is unloaded at the wrong station.
- A clerk at one station tries to hand over or release a parcel that is at another station.
- A parcel is marked collected twice, or collected before it has arrived.
- The collection code is guessed repeatedly.
- The notice sender fails half-way through a batch: on the next run nobody is sent the same notice twice and nobody is missed.
- A phone number typed as `07…`, `255…` or `+255…`: stored in one format.
- A sender name containing `<script>`.
- A request with an unknown JSON field, a body that is too large, or a body that is not JSON.
- The client disconnects in the middle of a request.

## It works when
- [ ] `go.mod` lists only the database driver, sqlc's runtime needs and goose (plus the standard library's own extended modules if you use them); there is no router or framework.
- [ ] No SQL is built by joining strings with user input; every query uses placeholders.
- [ ] A parcel's current status is always derivable from its hand-over records, and no hand-over record is ever edited or deleted.
- [ ] A clerk can never read or change another station's parcels except through the allowed hand-over; a test proves it.
- [ ] The tracking page shows no names and no phone numbers.
- [ ] Every form has CSRF protection, and every template output is escaped.
- [ ] `gofmt`, `go vet` and `go test ./...` are clean.
- [ ] The app is live as one binary under systemd over HTTPS, and stopping the service lets in-flight requests finish.
- [ ] The README explains the route list, the structure, how to migrate and deploy, and the sessions-or-token choice.

## Stretch change (transfer check)
The company adds a rule: a parcel not collected within seven days is flagged, the sender is notified, and after a manager approves it the parcel starts a return journey to the origin station. Add it as new hand-over states and a new notice, without editing past records and without copying role checks into handlers.

## Rebuild from memory (a week later)
Without looking: write the middleware chain again (request id and logging, panic recovery, "must be logged in") and one handler that reads a path wildcard and returns JSON, with `httptest` tests.

## Know before real use
Carrying parcels commercially falls under TCRA courier registration, which is the carrier's duty, not the software's; selling this to a carrier raises those rules for the carrier. Sender and receiver names and phone numbers are personal data, and a real SMS sender name needs registration by a registered business. Stay on invented people and the log or simulator sender while learning. See `resources/research/East Africa software problems for PHP projects.md`; it is not legal advice.
