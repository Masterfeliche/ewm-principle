# Modern .NET rewards learners who ship systems

In late 2026, .NET is a fast, cross-platform, Linux-and-container-first platform with a clean two-version support window. **.NET 11 (STS) shipped on 10 November 2026 with C# 15**, and **.NET 10 (LTS, November 2025) remains the production default**. Both are supported until **14 November 2028**, while .NET 8 and 9 went out of support on the same day .NET 11 arrived ([.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core); [Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). The core stack is ASP.NET Core with Minimal APIs and first-party OpenAPI and validation, EF Core 10, and Aspire for local orchestration and telemetry. Around it sit Visual Studio 2026, Rider and VS Code, and a testing world that is moving to Microsoft.Testing.Platform. The platform has absorbed so much (validation, OpenAPI, resilience, caching, OpenTelemetry hooks, container builds without a Dockerfile) that a beginner needs far fewer third-party libraries than five years ago. That matters, because a 2025 licensing wave turned MediatR, AutoMapper, MassTransit v9 and FluentAssertions v8 into paid products. The job market is the strongest argument for .NET over PHP. In the UK, **C# appears in about 7x as many permanent job ads as PHP (3,356 vs 470) and pays a £12,500 higher median** ([ITJobsWatch C#](https://www.itjobswatch.co.uk/jobs/uk/csharp.do); [ITJobsWatch PHP](https://www.itjobswatch.co.uk/jobs/uk/php.do)). But the .NET workforce skews senior and entry-level hiring has shrunk everywhere. The best path for a newcomer therefore has five stages: C# fundamentals on .NET 10, ASP.NET Core with EF Core, professional quality and deployment habits, production architecture, and finally distributed systems at scale. The goal at every stage is a deployed, tested artefact that looks one level above where the learner actually is.

## Two supported versions, both ending in November 2028

.NET ships a new major version every November. Even numbers are Long Term Support releases with three years of patches, and odd numbers are Standard Term Support releases. Starting with .NET 9, Microsoft lengthened STS from 18 to **24 months**, because out-of-band packages such as Aspire and Microsoft.Extensions.AI could pull STS dependencies into LTS apps ([.NET Blog](https://devblogs.microsoft.com/dotnet/dotnet-sts-releases-supported-for-24-months/); [InfoQ](https://www.infoq.com/news/2025/09/microsoft-extends-dotnet-sts)). One side effect is that an LTS and the following STS now end on the same day, so picking the newer STS release no longer shortens a project's runway. Users must stay on the latest patch to remain supported.

| Version | Released | Type | End of support | Status on 20 Nov 2026 |
|---|---|---|---|---|
| .NET 6 and 7 | 2021–2022 | LTS / STS | Nov 2024 / May 2024 | Out of support |
| .NET 8 | 14 Nov 2023 | LTS | **10 Nov 2026** | Out of support (final patch 8.0.34) |
| .NET 9 | 12 Nov 2024 | STS | **10 Nov 2026** | Out of support (final patch 9.0.23) |
| .NET 10 | 11 Nov 2025 | LTS | 14 Nov 2028 | Supported, patch 10.0.15; C# 14 |
| .NET 11 | 10 Nov 2026 | STS | 14 Nov 2028 | Supported, newest; C# 15 |
| .NET Framework 4.8 / 4.8.1 | 2019 / 2022 | Windows component | No end date | Maintained, not developed |

Source: [.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core); [.NET Framework lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-net-framework).

**A learner starting now should install the .NET 10 SDK, or .NET 11 to use C# 15.** Tutorials built on .NET 8 still teach mostly valid code, but they now target an unsupported runtime. The legacy line matters too. **.NET Framework 4.8.x has no announced end date** because, from 4.5.2 onward, it follows the lifecycle of the Windows release it ships with. Microsoft's own server products, including Exchange, SQL Server, SharePoint and Dynamics CRM, still use it as middleware ([Lifecycle FAQ](https://learn.microsoft.com/en-us/lifecycle/faq/dotnet-framework)). One near-term deadline exists: **4.6.2 ends on 13 January 2027**, which will push some legacy shops to at least 4.8.1 ([.NET Framework lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-net-framework)). In JetBrains' 2025 survey, **35% of .NET developers still used .NET Framework** ([JetBrains State of .NET 2025](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). Maintenance and migration work is a steady part of the market.

### C# 15 brings union types to a language already built for productivity

The language a beginner meets in 2026 is far more concise than the C# of the .NET Framework era. The essentials built up release by release ([C# version history](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-version-history)). C# 8 added **nullable reference types**, switch expressions and async streams. C# 9 brought **records**, init-only setters and top-level statements. C# 10 added file-scoped namespaces and global usings. C# 11 introduced `required` members, raw string literals and list patterns. C# 12 made **primary constructors** available to every class and added **collection expressions** (`[1, 2, ..other]`). C# 13 added `params` collections and a new `Lock` type.

C# 14 (with .NET 10) added **extension members**, which bring extension properties, operators and static members. It also added the **`field` keyword** for properties with a compiler-generated backing field, null-conditional assignment (`customer?.Order = ...`) and implicit span conversions ([What's new in C# 14](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-14)). **C# 15 (with .NET 11) headlines union types** (`public union Pet(Cat, Dog, Bird);`). The compiler checks that `switch` expressions cover every case. C# 15 also adds **closed hierarchies**, where a `closed` class can only be derived from inside its own assembly, so switches over it need no default arm. Rounding out the release are collection expression arguments (`[with(capacity: n), ..values]`), extension indexers and labeled `break`/`continue`. Only a redesigned memory-safety model remains preview ([What's new in C# 15](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-15)). Unions also work in System.Text.Json and in ASP.NET Core request bodies ([What's new in .NET 11](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-11/overview)).

These features carry different weight in daily work. Everyday code uses nullable references, records, pattern matching, primary constructors for injected services, collection expressions and async/await. Unions and closed hierarchies will change how teams model domain results, replacing the library-based Result and OneOf types. Span, `ref struct`, generic math and inline arrays remain specialist performance tools. **A useful mental model: modern C# sits between Kotlin and TypeScript in feel, with a statically compiled type system and generics that PHP still lacks.**

### Performance is a yearly product feature

Modern .NET treats performance as a release deliverable. Its runtime uses tiered JIT compilation with Dynamic PGO, which collects type and branch profiles at Tier 0 so that Tier 1 can devirtualize hot calls. Stephen Toub's annual post for .NET 11 shows examples such as generic virtual dispatch falling from 6.7 ns to 1.8 ns with zero allocation ([Performance Improvements in .NET 11](https://devblogs.microsoft.com/dotnet/performance-improvements-in-net-11/)). The largest .NET 11 runtime change is **Runtime Async**: the JIT and runtime, rather than the C# compiler, now build the async state machine. In Toub's micro-benchmarks, a synchronously completing two-layer async chain fell from 21.2 ns and 144 bytes to 6.2 ns and zero bytes ([Toub](https://devblogs.microsoft.com/dotnet/performance-improvements-in-net-11/)). Its release status is reported inconsistently, however. The Learn page says `net11.0` projects no longer need a preview flag ([What's new in .NET 11](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-11/overview)), the release announcement still calls it preview ([Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)), and Toub described it as opt-in. A learner should treat it as arriving, not settled. **Native AOT** compiles an app ahead of time into a self-contained native binary with fast startup and a small footprint. It is a publishing option with real trade-offs: no unrestricted reflection, and source generators are needed for JSON ([Native AOT deployment](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)).

The platform reaches well beyond the web. Desktop has WPF and WinForms, both still updated yearly, plus MAUI, which made CoreCLR its default runtime in .NET 11 ([What's new in .NET 10](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-10/overview); [Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). Unity is a major games outlet: **18% of .NET developers use it** ([JetBrains State of .NET 2025](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). AI is the newest growth area. .NET 11 promotes `Microsoft.Extensions.AI`, a `dotnet new mcpserver` template and Microsoft Agent Framework, and the ecosystem counts **over 589,000 unique NuGet packages** ([Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). In popularity, **27.8% of Stack Overflow's 2025 respondents use C#** ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/technology)). C# was TIOBE's Language of the Year for 2025 ([Visual Studio Magazine](https://visualstudiomagazine.com/Articles/2026/01/08/Csharp-Grabs-Language-of-the-Year-TIOBE-Predicts-TypeScript-Rise.aspx)), but it sits at #5 in November 2026 after an unexplained 4.26-point drop that more likely reflects TIOBE's methodology than real usage ([TIOBE](https://www.tiobe.com/tiobe-index/)).

## ASP.NET Core absorbs what used to be third-party libraries

ASP.NET Core is the centre of .NET backend work. **70% of .NET web developers use it**, against 28% for React and 25% for Blazor ([JetBrains State of .NET 2025](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). It ranked 4th among web frameworks at 19.9% in Stack Overflow's 2026 survey ([Visual Studio Magazine, Oct 2026](https://visualstudiomagazine.com/articles/2026/10/06/stack-overflow-2026-survey-vs-code-leads-visual-studio-takes-third.aspx)). Since .NET 9, Microsoft has consistently landed new features in **Minimal APIs** first:

- **.NET 9** replaced Swashbuckle in templates with the first-party `Microsoft.AspNetCore.OpenApi` package. The common pairing became `MapOpenApi()` with the Scalar UI ([Tim Deschryver](https://timdeschryver.dev/blog/what-about-my-api-documentation-now-that-swashbuckle-is-no-longer-a-dependency-in-aspnet-9.md); [codewithmukesh](https://codewithmukesh.com/blog/dotnet-swagger-alternatives-openapi)).
- **.NET 10** added built-in validation (`AddValidation()`, which returns 400 with problem details), Server-Sent Events and OpenAPI 3.1 by default. It also added Identity **passkeys**. Under cookie auth, API endpoints now return 401/403 instead of redirecting to a login page, a behaviour change many older tutorials miss ([ASP.NET Core 10 release notes](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0)).
- **.NET 11** added async validation, union types in JSON bodies, a `[ShortCircuit]` attribute and OpenAPI 3.2 by default (a breaking change). SignalR connections can now refresh authentication without reconnecting. Zstandard compression is on by default, and OpenTelemetry semantic conventions are built in ([ASP.NET Core 11 release notes](https://learn.microsoft.com/aspnet/core/release-notes/aspnetcore-11)).

Controllers and MVC remain fully supported and dominate existing enterprise code: **47% of .NET web developers use Web API and 27% use MVC** ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). A learner therefore needs both styles. On the front end, Blazor's unified "Web App" model combines static server rendering with interactive Server, WebAssembly and Auto modes. Microsoft's 2026 investment is concentrated on **static SSR with progressive interactivity**: .NET 11 added SSR client-side validation, a `CacheView` component and URL-based QuickGrid paging ([ASP.NET Core 11 release notes](https://learn.microsoft.com/aspnet/core/release-notes/aspnetcore-11)). That puts Blazor in the same design space as server-rendered HTMX apps. Teams with JavaScript skills keep pairing a React or Angular front end with an ASP.NET Core API, and UK ASP.NET Core ads mention **React in 38.4%** of cases ([ITJobsWatch ASP.NET Core](https://www.itjobswatch.co.uk/jobs/uk/asp.net%20core.do)).

### EF Core 10 is the safe data pairing through 2028

**EF Core 10 is an LTS release supported until 10 November 2028**, and it requires .NET 10 ([What's New in EF Core 10](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew)). Its headline changes give a learner a clear modern idiom. Complex types can now map to JSON and can be optional or structs, and Microsoft explicitly advises moving from owned entities to complex types for value objects. Named query filters allow separate "SoftDelete" and "Tenant" filters per entity, and LINQ gained `LeftJoin`/`RightJoin`. EF Core 10 also supports SQL Server 2025's native `json` and `vector` types, including `VectorDistance()` for retrieval-augmented generation. An analyzer now warns on string concatenation in `FromSqlRaw` ([EF Core 10](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew)). EF Core 11 adds `FullJoin`, fewer joins in generated SQL and experimental vector indexes, but it requires the STS runtime ([Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). EF Core is used by **42% of .NET developers** ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)), and Dapper remains the standard micro-ORM for hand-written hot-path SQL. Stack Overflow itself ran EF Core and Dapper side by side ([Packt](https://www.packtpub.com/en-at/learning/tech-news/stack-exchange-migrates-to-net-entity-framework-core-ef-core-stack-overflow-to-follow-soon)). The research found no reliable share figures for PostgreSQL versus SQL Server within .NET. Job ads, however, lean heavily on Microsoft's database: **82.7% of UK ASP.NET Core ads mention SQL and 73.4% Azure SQL Database** ([ITJobsWatch ASP.NET Core](https://www.itjobswatch.co.uk/jobs/uk/asp.net%20core.do)).

### The 2025 licensing wave makes patterns more durable than libraries

Several flagship community libraries went commercial in 2025–26. **AutoMapper v15 and MediatR v13** launched under Lucky Penny Software on 2 July 2025 with a dual RPL-1.5 or commercial licence. A free Community tier covers companies under $5M revenue, education and non-production use, and a missing licence key only logs a message ([Jimmy Bogard](https://www.jimmybogard.com/automapper-and-mediatr-commercial-editions-launch-today/)). **MassTransit v9** is commercial ("a commercial product that must be licensed"), while v8 stays permissive with security patches through 2026 ([NuGet MassTransit](https://www.nuget.org/packages/MassTransit/9.1.1); [Milan Jovanović](https://milanjovanovic.tech/blog/mediatr-and-masstransit-going-commercial-what-this-means-for-you)). **FluentAssertions v8** moved to a paid licence via Xceed in January 2025 ([InfoQ](https://www.infoq.com/news/2025/01/fluent-assertions-v8-license)). Serilog, Polly and FluentValidation remain free, and Hangfire's core is LGPLv3 with paid add-ons ([codewithmukesh](https://codewithmukesh.com/blog/15-essential-libraries-for-aspnet-core/); [Hangfire](https://hangfire.io/pricing)).

Common replacements now include source-generated mediators such as martinothamar's `Mediator`, Wolverine, Rebus, raw transport clients, and plain hand-written mapping ([GitHub Mediator](https://github.com/martinothamar/Mediator); [Milan Jovanović](https://milanjovanovic.tech/blog/mediatr-and-masstransit-going-commercial-what-this-means-for-you)). The practical lesson for a learner is to learn **mediator, CQRS, mapping, validation pipelines, outbox and messaging as patterns**, then choose a library with its licence in mind. Licensing has become an architecture decision.

### Aspire turns "run my whole system locally" into one command

**Aspire 13 (11 November 2025) dropped the ".NET" prefix** and became a polyglot application platform with first-class Python and JavaScript support. It added an `aspire do` pipeline for build, publish and deploy ([Aspire 13](https://devblogs.microsoft.com/aspire/aspire13/); [InfoQ](https://www.infoq.com/news/2025/11/dotnet-aspire-13-release)). It orchestrates an API, database, cache and queue locally, and it provides an OpenTelemetry dashboard and "service defaults" (telemetry, health checks, resilience) in one project. In .NET 11, `dotnet watch` integrates with the Aspire AppHost ([Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). Aspire is now Microsoft's default answer to running a multi-service system locally with telemetry. A learner should reach for it after the fundamentals, because it orchestrates pieces the learner must already understand.

## Tooling splits evenly between Visual Studio and Rider

The editor landscape has three serious options:

- **Visual Studio 2026** (GA 11 November 2025) is Windows-only. Microsoft markets it as "AI-native", with Copilot agents, a Profiler Agent and Copilot-driven app modernization. It ships monthly updates and loads large solutions faster than VS 2022 ([VS Blog](https://devblogs.microsoft.com/visualstudio/visual-studio-2026-is-here-faster-smarter-and-a-hit-with-early-adopters)).
- **JetBrains Rider** is cross-platform and **free for non-commercial use since October 2024**, which suits learners ([JetBrains](https://blog.jetbrains.com/blog/2024/10/24/webstorm-and-rider-are-now-free-for-non-commercial-use/)).
- **VS Code with C# Dev Kit** is free for individuals and teams of up to five ([VS Code FAQ](https://code.visualstudio.com/docs/csharp/cs-dev-kit-faq)).

Visual Studio for Mac was retired on 31 August 2024 ([VS Blog](https://devblogs.microsoft.com/visualstudio/visual-studio-for-mac-retirement-announcement/)). Among C# developers, **Rider rose from 35% to 44% in a year, nearly matching Visual Studio's 45%**, while VS Code holds 9% ([JetBrains State of .NET 2025](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). JetBrains' sample probably over-represents its own users, but the trend is clear. In March 2026 ReSharper also arrived for VS Code, Cursor and similar editors ([JetBrains](https://blog.jetbrains.com/dotnet/2026/03/05/resharper-for-visual-studio-code-cursor-and-compatible-editors-is-out/)). AI assistance is effectively standard: **63% of .NET developers have used or tried GitHub Copilot**, against 67% for ChatGPT ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)).

The .NET 10 SDK set several modern defaults ([What's new in .NET 10 SDK](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-10/sdk)):

- **`dotnet new sln` creates `.slnx` files** ([breaking change](https://learn.microsoft.com/en-us/dotnet/core/compatibility/sdk/10.0/dotnet-new-sln-slnx-default)).
- **NuGet Audit checks transitive packages by default** for `net10.0` projects ([NuGet audit change](https://learn.microsoft.com/en-us/dotnet/core/compatibility/sdk/10.0/nugetaudit-transitive-packages)).
- Framework-provided packages are pruned, which cuts false-positive vulnerability warnings.
- `dnx` / `dotnet tool exec` runs tools without installing them.
- **File-based apps** let a beginner run `dotnet run app.cs` with no project file, with `#:package` directives and native publishing ([file-based apps](https://learn.microsoft.com/dotnet/core/sdk/file-based-apps)).

.NET 11 extends file-based apps with `#:include`, adds a `--min-publish-age-hours` supply-chain control for NuGet sources, and defaults test templates to xUnit v3 ([What's new in .NET 11](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-11/overview)). File-based apps lower the entry barrier for beginners more than any change in years.

Code quality starts with the Roslyn analyzers built into the SDK, configured through `.editorconfig` and tightened with warnings-as-errors in CI. Code-style rules are off on command-line builds unless explicitly enabled ([code analysis overview](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview)). SonarQube, rebranded from SonarCloud and SonarLint in 2024, analyses C# up to version 14 ([Sonar](https://www.sonarsource.com/fr/knowledge/languages/csharp)).

### Testing moves to Microsoft.Testing.Platform

Two test frameworks lead: **xUnit (48%) and NUnit (45%), with MSTest at 16%** ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). The big migration of 2025–26 is the test runner. **Microsoft.Testing.Platform (MTP) is replacing VSTest.** In .NET 10, `dotnet test` supports it natively through a `global.json` setting ([migrating to MTP](https://learn.microsoft.com/en-us/dotnet/core/testing/migrating-vstest-microsoft-testing-platform)). **xUnit v3 4.0 (14 August 2026) dropped MTP v1 and defaults to MTP v2** ([xUnit 4.0.0](https://xunit.net/releases/v3/4.0.0)), and Microsoft recommends MSTest.Sdk on MTP for new MSTest projects ([MSTest intro](https://learn.microsoft.com/dotnet/core/testing/unit-testing-mstest-intro)). CI scripts written for VSTest arguments need rewriting.

For assertions, the paid FluentAssertions v8 pushed teams to the Apache-2.0 fork **AwesomeAssertions** or to Shouldly ([NuGet AwesomeAssertions](https://www.nuget.org/packages/AwesomeAssertions)). Moq's 2023 SponsorLink episode, in which a release quietly collected hashed git emails, sent many teams to NSubstitute ([Snyk](https://snyk.io/blog/moq-package-exfiltrates-user-emails/)). Integration tests typically pair WebApplicationFactory with **Testcontainers 4.x** ([NuGet Testcontainers](https://packages.nuget.org/packages/Testcontainers)). Playwright handles browser tests (9% usage), Stryker.NET handles mutation testing and now has an MTP runner, and BenchmarkDotNet handles micro-benchmarks ([Stryker](https://stryker-mutator.io/blog/stryker-net-mtp-runner/); [JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). For production diagnostics there is a cross-platform CLI suite: `dotnet-counters`, `dotnet-trace`, `dotnet-dump`, `dotnet-gcdump` and `dotnet-monitor` ([diagnostics tools](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/tools-overview)).

Together these define the CI pipeline a learner should copy from the first API project onward:

1. `actions/setup-dotnet`, pinned to the SDK in `global.json`
2. `dotnet restore`, failing on high or critical NuGet Audit warnings
3. `dotnet format --verify-no-changes`
4. `dotnet build -warnaserror`
5. `dotnet test` on MTP with coverage
6. Testcontainers integration tests
7. A CodeQL or Sonar scan
8. `dotnet publish /t:PublishContainer`

Microsoft documents most of these steps for GitHub Actions ([GitHub Actions and .NET](https://learn.microsoft.com/en-us/dotnet/devops/github-actions-overview)).

## A Linux container behind ingress is the default deployment

The standard production shape is **Kestrel, ASP.NET Core's built-in server, inside a Linux container**, behind a TLS-terminating proxy or ingress such as Nginx or a cloud load balancer. Microsoft notes that Kestrel is "great for serving dynamic content" while a proxy offloads static files, compression and HTTPS ([Linux + Nginx](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/linux-nginx)). Behind a proxy, `UseForwardedHeaders` must run first, and only loopback proxies are trusted by default. On a VPS, the official systemd unit uses **`KillSignal=SIGTERM`**. The doc warns against SIGINT, which older tutorials used, because .NET listens for SIGTERM to shut down gracefully ([Linux + Nginx](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/linux-nginx)). **`dotnet publish /t:PublishContainer` builds an OCI image with no Dockerfile.** It can push straight to a registry or write a tarball for scanning ([Containerize with dotnet publish](https://learn.microsoft.com/en-us/dotnet/core/containers/sdk-publish)). For .NET 10, Microsoft dropped Debian-based images in favour of Ubuntu Chiseled (distroless) and Azure Linux images ([dotnet-docker #6860](https://github.com/dotnet/dotnet-docker/issues/6860)). Windows and IIS hosting is now mostly for legacy .NET Framework apps. No Windows Server licence is required for modern .NET.

Native AOT is a targeted optimisation, not a default. It cuts disk footprint, startup time and memory, which raises deployment density and speeds orchestrator rollouts. It supports Minimal APIs only partially, and **MVC, Blazor Server, Session and non-JWT authentication are not supported** ([ASP.NET Core Native AOT](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/native-aot)). It suits serverless functions, scale-to-zero services, workers and CLIs, and it does not suit Razor-heavy monoliths.

### Deployment targets run from a single VPS to Kubernetes

The deployment spectrum starts with a **VPS** running systemd and Nginx, which is the cheapest option. Next are serverless containers. **Azure Container Apps** bills per second, scales to zero by default and includes a monthly free grant of 180,000 vCPU-seconds and 2 million requests ([ACA pricing](https://azure.microsoft.com/en-us/pricing/details/container-apps/?cdn=disable)). Functions are an option too. **AWS Lambda added a managed .NET 10 runtime on 8 January 2026**, and file-based C# Lambda functions default to Native AOT for fast cold starts ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/01/aws-lambda-dot-net-10/); [AWS Compute Blog](https://aws.amazon.com/blogs/compute/net-10-runtime-now-available-in-aws-lambda)). At the top end are orchestrators (AKS, EKS, GKE). Aspire bridges local development and these targets. `aspire publish` emits Compose files, Kubernetes manifests or Bicep, and `aspire deploy` applies them ([aspire.dev](https://aspire.dev/deployment/overview/)). Aspire 13.3 (May 2026) added Helm chart generation for Kubernetes, but in preview ([What's new in Aspire 13.3](https://devblogs.microsoft.com/aspire/whats-new-aspire-13-3)).

Database migrations are where beginners most often break production. Microsoft's guidance, updated in August 2026, is precise. **Use an EF Core migration bundle**, a single-file executable built in CI, or an idempotent SQL script when a DBA must review the change. Run it as a one-shot job, because "don't make every application replica run migrations from its entrypoint". Give the migration identity schema rights and the app identity only data rights ([Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying)). EF 9+ takes a database-wide migration lock and throws on pending model changes, which CI can check ([same](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying)). A zero-downtime release then follows from the sources. Make schema changes backwards-compatible (expand, then contract), run the bundle before the rollout, roll replicas behind readiness health checks, and rely on SIGTERM draining.

### Scaling out depends on staying stateless

ASP.NET Core scales horizontally when the app holds no in-process state. The in-box building blocks for 2026 are listed below.

**HybridCache**, GA since March 2025, combines an in-process L1 cache with an optional Redis L2. Its stampede protection joins concurrent callers for the same key, but only per instance, not across servers ([.NET Blog](https://devblogs.microsoft.com/dotnet/hybrid-cache-is-now-ga/); [ITNext](https://itnext.io/how-hybridcache-prevents-cache-stampedes-in-asp-net-core-and-where-it-stops-4cb11f2e1f9a)).

**Output caching and rate limiting** are first-party middleware.

**`AddStandardResilienceHandler`** wraps every outbound HttpClient call in a Polly v8 chain: rate limiter, 30-second total timeout, three jittered retries, circuit breaker and 10-second attempt timeout. Retries apply to POST by default, so `DisableForUnsafeHttpMethods()` is needed to avoid duplicate writes ([HTTP resilience](https://learn.microsoft.com/en-us/dotnet/core/resilience/http-resilience)).

**Worker services** (`BackgroundService`) handle queued work and support Native AOT. On Container Apps, KEDA scales them on queue depth ([ACA pricing](https://azure.microsoft.com/en-us/pricing/details/container-apps/?cdn=disable)).

Observability is unusually clean in .NET. The platform's own `ILogger`, `Meter` and `ActivitySource` APIs emit the data, and the OpenTelemetry SDK exports it over OTLP to the Aspire Dashboard, Azure Monitor or Prometheus with Grafana. Aspire ServiceDefaults wires this up even without the rest of Aspire ([.NET observability with OTel](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/observability-with-otel)).

Performance claims deserve care. Microsoft markets ASP.NET Core at about **2.05M JSON responses per second in TechEmpower Round 23, against Node.js at about 224K** ([dotnet.microsoft.com](https://dotnet.microsoft.com/en-us/learn/aspnet/what-is-aspnet-core)). But that is a vendor-chosen synthetic test, run on hardware Microsoft donated, using tuned implementations unlike typical apps ([TechEmpower](https://www.techempower.com/blog/tag/tfb/); [dusted.codes](https://dusted.codes/how-fast-is-really-aspnet-core)). Microsoft's internal migrations are more telling, though also self-reported. Teams' Push Notification API gained **48% throughput moving from .NET Framework 4.7.2 to .NET 8** ([.NET Blog](https://devblogs.microsoft.com/dotnet/modernizing-push-notification-api-for-teams/)). Office Online RTC cut CPU by 30% and API latency by over 50% ([.NET Blog](https://devblogs.microsoft.com/dotnet/office-rtc-dotnet-migration/)).

The canonical outside case study is Stack Overflow, and its lesson runs against microservice fashion. It served a top-tier website from a cached monolith and a scaled-up SQL Server. When it moved to Google Cloud in 2025, it ran SQL Server on a 128-vCPU, 3.9 TB VM and **"disabled half of the cores to save on licensing costs"**. Its remaining .NET Framework apps went onto a Windows Kubernetes cluster ([Stack Overflow blog](https://stackoverflow.blog/2025/08/28/moving-the-public-stack-overflow-sites-to-the-cloud-part-1/)). Two lessons follow. Microservices are not a prerequisite for scale on .NET. And on a Linux stack, SQL Server licensing, paid libraries and APM ingestion drive costs more than compute does.

## The UK market pays C# a £12,500 premium over PHP

The demand data favours .NET clearly. In the six months to 20 November 2026, UK permanent IT ads showed the following ([ITJobsWatch C#](https://www.itjobswatch.co.uk/jobs/uk/csharp.do); [.NET](https://www.itjobswatch.co.uk/jobs/uk/.net.do); [ASP.NET Core](https://www.itjobswatch.co.uk/jobs/uk/asp.net%20core.do); [PHP](https://www.itjobswatch.co.uk/jobs/uk/php.do)):

| Skill | Ads 2026 / 2025 / 2024 | Share of IT ads 2026 | Median salary 2026 |
|---|---|---|---|
| C# | 3,356 / 1,918 / 4,678 | 2.72% | £62,500 |
| .NET | 2,871 / 1,583 / 4,013 | 2.33% | £62,500 |
| ASP.NET Core | 549 / 70 / 154 | 0.45% | £55,000 |
| PHP | 470 / 395 / 1,103 | 0.38% | £50,000 |

Share and count move in opposite directions here. C# ad counts rose 75% year on year while their share fell, which means the total number of tracked ads grew sharply. The counts and the **C#-to-PHP ratio (about 4.9x in 2025, 7.1x in 2026)** say more than share alone. ASP.NET Core's jump from 70 to 549 ads most likely reflects advertisers naming the framework explicitly rather than a sevenfold surge in demand. **UK C# contract roles pay a median £500 a day** ([ITJobsWatch contracts](https://www.itjobswatch.co.uk/contracts/uk/csharp.do)). Globally, C# usage is 27.8% against PHP's 18.9%, and ASP.NET Core at 19.7% is used about twice as much as Laravel at 8.9% ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/technology)). Vetted remote platforms put senior .NET developers around $44 an hour ([Lemon.io benchmark](https://lemon.io/wp-content/media/2026/09/Lemon-Rate-Benchmark-Report.pdf)). That is roughly level with senior Laravel rates, so freelancing does not show the same gap as UK salaries.

Employers want a predictable stack. **UK C# ads co-mention .NET in 68.4% of cases, Azure in 45.8%, SQL in 32.8%, CI/CD in 26.8%, full-stack in 25.2% and JavaScript in 23.5%** ([ITJobsWatch C#](https://www.itjobswatch.co.uk/jobs/uk/csharp.do)). ASP.NET Core ads add Entity Framework (36.1%), microservices (31.3%) and Docker (26.4%) ([ITJobsWatch ASP.NET Core](https://www.itjobswatch.co.uk/jobs/uk/asp.net%20core.do)). Azure's weight is distinctive: **47% of C# developers use Azure against 18% of developers in other languages** ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)).

The entry rung is the hard part, as in PHP. **Only 16% of .NET developers have two years or less experience, while 24% have 16 or more** ([JetBrains](https://lp.jetbrains.com/the-state-of-dotnet-2025/)). Across the industry, Stanford's Erik Brynjolfsson reports about a 20% employment decline for software developers aged 22–26, with mid and senior hiring stable ([IEEE Spectrum](https://spectrum.ieee.org/ai-effect-entry-level-jobs)). Germany's advertised junior developer roles have halved ([heise](https://heise.de/-10625967)). Researchers cannot yet separate AI's effect from the economic cycle, and no source splits .NET postings by seniority. The safe reading is that a junior portfolio must show mid-level habits: tests, containers, CI/CD and a cloud deployment.

Certifications have shifted. **AZ-204 (Azure Developer Associate) retired on 31 July 2026**, replaced by **AI-200 Azure AI Cloud Developer Associate**, part of Microsoft's pivot to AI-centred credentials ([Microsoft Learn](https://learn.microsoft.com/en-us/credentials/certifications/azure-developer/); [Microsoft Tech Community](https://techcommunity.microsoft.com/blog/skills-hub-blog/the-ai-job-boom-is-here-are-you-ready-to-showcase-your-skills/4494128)). No data shows that job ads require Microsoft certifications, so certifications act as tie-breakers. Azure skills, by contrast, appear in almost half of all ads.

### The staged path from zero to scalable systems

No official Microsoft "mastery order" exists, and no rigorous data measures how long each stage takes. The sequence below synthesises the platform's structure, Microsoft's direction of travel and the skills employers co-advertise. **The durations are estimates for 10–20 hours of study a week, not sourced figures.** Community estimates of 9–18 months to a junior-ready portfolio look optimistic for the 2026 market. Each stage ends in a portfolio artefact, because in this market the artefact matters more than the course certificate.

| Stage | Focus | Prove it with |
|---|---|---|
| **1. C# and .NET foundations** (about 0–3 months) | .NET 10 SDK and the `dotnet` CLI; file-based apps first, then SDK-style projects with `Nullable` and `ImplicitUsings`. Value vs reference types, nullability, control flow, methods, pattern matching. Classes, interfaces, records, generics, collections, LINQ (deferred execution), exceptions and `IDisposable`. async/await with cancellation tokens (never `.Result`). NuGet and Git. Skip .NET Framework and pre-.NET 6 tutorials. | A LINQ-heavy CLI tool (CSV report or budget app) with file persistence, plus the free Foundational C# exercises |
| **2. ASP.NET Core and EF Core** (about 3–8 months) | The Generic Host: DI lifetimes, configuration with the Options pattern, `ILogger`. Middleware pipeline. Minimal APIs and controllers, built-in OpenAPI with Scalar, built-in validation, ProblemDetails. EF Core 10: migrations, complex types, query filters, raw SQL and Dapper on SQL Server or PostgreSQL. Identity with passkeys, JWT bearer, authorization policies. xUnit v3 on MTP, WebApplicationFactory, Testcontainers. A thin React or Blazor static SSR front end. | A tested CRUD REST API with auth and OpenAPI docs, with a small front end, deployed to App Service or a VPS: junior-employable |
| **3. Professional engineering** (about 8–15 months) | `Directory.Build.props`, Central Package Management, analyzers with warnings-as-errors, `dotnet format`, NuGet Audit. A GitHub Actions pipeline and `/t:PublishContainer` images. HybridCache with Redis, output caching, rate limiting, the standard resilience handler. Background work with `BackgroundService` or Hangfire. Serilog and OpenTelemetry. Migration bundles and expand/contract schema changes. Vertical slices or Clean Architecture, with mediator and mapping learned as patterns and licence-aware library choices. | A modular monolith (booking or invoicing) with CI/CD, containers, caching, background jobs and dashboards: looks mid-level |
| **4. Production architecture and Azure** (about 1–2 years) | Aspire AppHost and ServiceDefaults. Azure Container Apps or AKS with Bicep or Terraform, managed identity and Key Vault. Messaging with Azure Service Bus or RabbitMQ through Wolverine, Rebus, raw clients or licensed MassTransit, plus the outbox pattern. SignalR and gRPC. Zero-downtime releases with health checks and SIGTERM draining. Profiling with `dotnet-counters`/`dotnet-trace` and BenchmarkDotNet. Optionally AI-200. | The monolith split into two or three services with messaging and traces, deployed with IaC and released without downtime |
| **5. Systems, scale and specialism** (2+ years) | Stateless horizontal scaling, KEDA autoscaling, read replicas and connection pooling. Native AOT and trimming where cold start or density matters. Span/Memory, allocation awareness, GC modes. C# 15 unions and closed hierarchies for domain modelling. k6 or NBomber load tests. A specialism chosen by market: .NET Framework migration, Azure platform engineering, AI and MCP services, Blazor, or Unity. Orleans or Dapr only if a problem demands them. | A load-tested production system with SLO dashboards and a written performance and cost report |

The free and low-cost resources are strong through stage 2. Microsoft Learn and the free **Foundational C# certification on freeCodeCamp** offer about 35 hours of training plus an 80-question exam. That offer was announced in 2023 and its 2026 availability was not confirmed ([.NET Blog](https://devblogs.microsoft.com/dotnet/announcing-foundational-csharp-certification/)). [Exercism's C# track](https://exercism.org/tracks/csharp) offers mentored practice. **Mark J. Price's *C# 14 and .NET 10* (10th edition, November 2025)** covers the whole current platform ([O'Reilly](https://www.oreilly.com/library/view/c-14-and/9781836206637/)). Andrew Lock's [blog and book](https://andrewlock.net/) are the standard for ASP.NET Core internals. Microsoft's [eShop reference app](https://github.com/dotnet/eShop) is the stage 4 blueprint. Two classics are older but still the best on their subjects: Jon Skeet's *C# in Depth*, which stops at C# 7, and *Dependency Injection Principles, Practices, and Patterns* from 2019.

## PHP versus .NET for the same learner

Read side by side, the two ecosystems are closer in maturity than their reputations suggest. Both ship annually every November: PHP 8.6 arrived on 19 November 2026 and .NET 11 on 10 November ([php.net](https://www.php.net/releases/8.6/en.php); [Announcing .NET 11](https://devblogs.microsoft.com/dotnet/?p=61205)). Both have a funded flagship web framework, a security-aware package manager and a modern test stack. Both face the same thin entry rung. They differ in what the platform gives you, what the market pays, and how hard the first months are.

| Dimension | PHP (late 2026) | .NET (late 2026) |
|---|---|---|
| Release and support | Annual minors; 2 years active + 2 security; 8.6 newest, 8.4 the practical floor | Annual majors; LTS 3 years, STS 2 years; .NET 10 LTS and .NET 11 STS both to Nov 2028 |
| Type system | Gradual typing, no native generics; PHPStan docblocks fill the gap | Static typing, generics, nullable references, C# 15 unions checked by the compiler |
| Dominant web stack | Laravel 13 (Symfony components underneath) | ASP.NET Core (Minimal APIs + MVC) with EF Core 10 |
| Batteries included | Framework supplies most features; toolchain is community-led (Composer, PHPStan, Pest) | Platform supplies OpenAPI, validation, DI, caching, resilience, telemetry and container builds |
| Licensing risk | Core tools free; commercial layer is hosting (Laravel Cloud, Forge) | Several popular libraries went paid in 2025–26 (MediatR, AutoMapper, MassTransit v9, FluentAssertions v8) |
| Runtime model | Shared-nothing FPM by default; worker mode (FrankenPHP, Octane) adds state-leak risks | Long-running Kestrel process by default; state discipline expected from day one |
| Hosting entry cost | Cheapest shared hosting and VPS on the market; WordPress-scale reach | Linux containers, VPS, ACA scale-to-zero, Lambda; SQL Server licensing is the cost trap |
| UK perm ads (6 months to Nov 2026) | 470, median £50,000, flat for three years | C# 3,356, median £62,500 |
| Global usage (SO 2025) | PHP 18.9%; Laravel 8.9% | C# 27.8%; ASP.NET Core 19.7% |
| Distinct job pools | WordPress, Drupal, Shopware, Adobe Commerce agencies; legacy PHP 7 upgrades | Enterprise and Azure shops, .NET Framework migration, desktop, Unity |
| Learning curve | Gentler first month; output in a browser in minutes | Steeper first month (types, async, DI), less to unlearn later |

Sources: [PHP ecosystem figures](https://www.php.net/supported-versions.php); [ITJobsWatch PHP](https://www.itjobswatch.co.uk/jobs/uk/php.do); [ITJobsWatch C#](https://www.itjobswatch.co.uk/jobs/uk/csharp.do); [Stack Overflow 2025](https://survey.stackoverflow.co/2025/technology); [Laravel 13](https://laravel.com/docs/13.x/releases); [PHP Foundation on FrankenPHP](https://thephp.foundation/blog/2025/05/15/frankenphp/).

Three differences matter most for a learner aiming at scalable systems. First, **.NET front-loads the hard concepts**: static types, async, dependency injection and long-lived process state are all present in the first API. PHP lets a beginner postpone them until static analysis and worker mode force the issue. The .NET path is slower for the first three months and smoother after that. Second, **.NET's platform owns more of the production stack**. Container images, OpenTelemetry, resilience, caching, migration bundles and orchestration (Aspire) are first-party and documented together, whereas a PHP learner assembles the equivalent from Laravel, Composer packages and hosting products. Third, **the market gap is real but regional and role-shaped**. UK data shows C# with roughly seven times PHP's permanent ads and a higher median. Senior freelance rates on vetted platforms are similar, at around $44 an hour for .NET against a $45–54 median for Laravel ([Lemon.io benchmark](https://lemon.io/wp-content/media/2026/09/Lemon-Rate-Benchmark-Report.pdf); [Lemon.io Laravel](https://lemon.io/rate-calculator/laravel-developers/)). PHP also keeps a large agency and CMS market that .NET does not reach. A learner who wants salaried enterprise employment, Azure, or a path into desktop, games or AI services should choose .NET. A learner who wants freelance web work, fast first results, or the WordPress and e-commerce economy has a sound case for PHP. Both paths end in the same place: the stage 5 skills of stateless scaling, database discipline, observability and load-tested releases transfer almost unchanged between them.

## Conclusion

The research inverts a common assumption about .NET. Its barrier is no longer cost or Windows: the SDK, Rider for non-commercial use, VS Code, Linux containers and scale-to-zero hosting are all free or nearly free. The real barrier is conceptual. .NET expects types, async, DI and process lifetime to be understood early. In return, Microsoft now ships most of what a production system needs inside the platform, so first-party features have become the safest bet against licence churn in the wider ecosystem. The 2025 commercial wave reinforces this: a learner who masters patterns and in-box features is insulated, while one who learns "MediatR plus AutoMapper" inherits a licensing question. The job data adds a sharper point. Demand is strongest for exactly the profile tutorials rarely produce: a C# developer who can also operate Azure, SQL, CI/CD and containers. So the learner should deploy something from stage 2 onward rather than treat deployment as an advanced topic.

Three shifts are worth watching, because they will redefine "mastery" over the .NET 12 LTS cycle expected in November 2027. The first is whether Runtime Async and C# 15 unions become everyday defaults or stay specialist. The second is whether Aspire's Kubernetes and polyglot deployment leave preview and become the standard path from laptop to cloud. The third is whether Microsoft's AI push, through Microsoft.Extensions.AI, MCP templates, Agent Framework and the AI-200 certification, turns "AI services" into a mainstream .NET job category the way ASP.NET Core did for web APIs. Two questions remain open: the true junior-versus-senior split in .NET hiring, and whether TIOBE's sharp 2026 drop for C# reflects anything real.
